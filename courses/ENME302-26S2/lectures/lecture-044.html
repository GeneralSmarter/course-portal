Detailed notes

Parameter sweeps and plotting

The lecturer demonstrated a workflow for extracting data from a parameter sweep and plotting it in a COMSOL graph.

A 1D plot group can contain several point graphs. These child graphs can be plotted on the same parent plot group, allowing quantities from different solutions or cases to be compared directly. An example involved plotting stress at a midpoint or lower boundary for several element-order cases.

For a single scalar value that must be extracted from many entries, the global evaluation feature can be used. The evaluated quantity might be:

• The number of degrees of freedom.

• A value at the final time step.

• A temperature at a selected point.

• An objective-function value.

For a stationary study, a final time does not apply. For a time-dependent study, the required time or time range must be selected.

Solutions from different cases can be copied or saved separately. The lecturer had saved solutions for linear, quadratic, and cubic element cases so that they could be plotted together. The important workflow is:

1. Compute or generate the parameterised solutions.

2. Save or copy the solutions if they are not automatically retained.

3. Select the required dataset.

4. Evaluate the quantity of interest.

5. Plot it against the parameter being varied.

If two parameters are varied, the resulting table or plot must distinguish the two parameter dimensions. The table orientation can be changed using inner and outer solution settings. One arrangement places time values in columns for each parameter value; reversing the setting exchanges the roles of rows and columns.

Optimisation workflow

The cooling-rod example was used to illustrate optimisation. The goal was to find a parameter value that caused the temperature to reach approximately 50 degrees at a specified location or time.

The general workflow is:

1. Select a control variable, such as alpha.

2. Define an objective function based on the desired result.

3. Perform a parameter sweep to explore the objective-function space.

4. Inspect the resulting objective values to select a sensible interval.

5. Apply an optimisation method over that interval.

6. Save multiple solutions if comparison of the search process is useful.

The objective function was described conceptually as the objective value plotted against the control variable. The lecturer gave an example involving a temperature difference from a target value, squared to produce a quadratic loss:

\[

J(\alpha) = \left[T(\alpha)-T_{\mathrm{target}}\right]^2

\]

The transcript indicates that the target temperature in the example was 50, although the precise units and whether the value was evaluated at a point or as an averaged quantity depend on the particular model setup.

A parameter sweep is useful because the shape of the objective function is initially unknown. It helps identify an interval in which an optimiser can search. The lecturer described a bounded optimisation method using a quadratic approximation: the method samples the objective function, fits a quadratic approximation, moves towards the estimated minimum, and repeats the process.

The objective-function table may already contain the values needed for plotting. If all optimisation solutions are saved, the solutions can also be compared directly in a plot.

Heat flux

The lecturer discussed calculating heat flux from the temperature distribution solved in Python or COMSOL. Temperature values are available at nodal points, including boundary and adjacent interior points.

The one-dimensional heat-flux expression is:

\[

q_x=-k\frac{\partial T}{\partial x}

\]

where:

• \(q_x\) is the heat flux in the \(x\)-direction.

• \(k\) is the thermal conductivity.

• \(T\) is temperature.

• \(\partial T/\partial x\) is the temperature gradient.

The transcript sometimes refers to thermal conductivity as \(k\) and sometimes as \(\kappa\). These represent the same coefficient in the context of the lecture.

At a boundary, the temperature derivative can be approximated using a one-sided finite difference. For example, at a left boundary, a forward difference can be used:

\[

\left.\frac{\partial T}{\partial x}\right|_{x_0}

\approx

\frac{T_1-T_0}{\Delta x}

\]

The corresponding approximate heat flux is:

\[

q_x(x_0)

\approx

-k\frac{T_1-T_0}{\Delta x}

\]

The lecturer also demonstrated using a gradient operation for plotting vector arrows or quivers. For the assignment, the simpler boundary-specific expression was recommended because the heat flux was required at known boundaries.

To calculate the total or average heat flux across a boundary, a line integration can be used. The purpose is to compare how much heat enters the patty and how much leaves it. A point graph gives heat flux at a selected point, whereas a line integration gives an integrated quantity over a boundary. The exact normal-direction convention should be checked when interpreting signs.

Mesh convergence

The assignment includes mesh convergence for both the simpler 2D case and the full 3D patty case. The objective is to demonstrate that the numerical solution is no longer changing significantly as the spatial discretisation is refined. The lecturer also referred to temporal discretisation, so time-step sensitivity may need to be considered for transient results.

A qualitative method is to plot several solution curves on the same axes and inspect whether they overlap. If curves overlap, zooming into the relevant region can make their closeness more visible.

A more direct method is to select a dependent-variable value at a fixed location and time, then plot that value against:

• Number of degrees of freedom.

• Number of mesh elements.

• A mesh-resolution parameter.

The same spatial point and time must be used for every mesh. This provides a like-for-like comparison.

Using the minimum value over the entire domain can be problematic. As the mesh is refined, the location of the interpolated minimum may move. The reported minimum may therefore represent different physical locations for different meshes. The comparison is then not strictly between equivalent quantities.

The lecturer made an analogous point about maximum stress near a concentration or singularity: the maximum can continue increasing as the mesh is refined. In such cases, the extreme value is not a reliable convergence measure. A fixed point or a clearly defined physical region is generally safer.

For the heat-equation model, the field is not strongly nonlinear, so the main requirement is to show that the selected quantity has stabilised under mesh refinement.

Structured mesh parameterisation

For a rectangular region, a mapped structured mesh can be used. The lecturer described a parameter sweep over \(N_y\), the number of elements in the \(y\)-direction.

The number of elements in the \(x\)-direction should also be controlled as the mesh is refined. In the example, it was coupled using:

\[

N_x=2N_y

\]

This produces rectangular elements. To produce approximately square elements, the ratio between the physical domain dimensions must also be considered.

The recommended strategy is to use one parameter to drive mesh generation, then perform a parameter sweep over that parameter. A quantity of interest can then be plotted against the resulting mesh resolution.

Degrees of freedom are related to the number of equations in the assembled system. The relationship depends on:

• The number of nodes.

• The number of unknowns per node.

• The physical fields being solved.

• The dimensionality of the model.

Heat-equation discretisation

The lecture returned to the governing heat equation and its finite-difference discretisation. The transcript identifies the method as an FTCS scheme, meaning forward in time and central in space.

The general variable-conductivity heat equation is represented in conservation form as:

\[

\rho C_p\frac{\partial T}{\partial t}

=

\nabla\cdot\left(\kappa\nabla T\right)

\]

where:

• \(\rho\) is density.

• \(C_p\) is specific heat capacity.

• \(T\) is temperature.

• \(\kappa\) is thermal conductivity.

The transcript’s displayed equation is heavily corrupted by automated transcription, so the exact notation used in class cannot be recovered with confidence. The conservation-form equation above is the standard interpretation of the terms spoken in the lecture.

For an explicit scheme, the spatial derivative terms on the right-hand side are evaluated using the previous time level. In two dimensions, the conductivity-weighted flux terms involve half-index locations such as \(i+\frac{1}{2}\) and \(j+\frac{1}{2}\).

For a uniform grid, a representative explicit discretisation is:

\[

\rho C_p

\frac{T_{i,j}^{n+1}-T_{i,j}^{n}}{\Delta t}

=

\frac{1}{\Delta x}

\left[

\kappa_{i+\frac12,j}

\frac{T_{i+1,j}^{n}-T_{i,j}^{n}}{\Delta x}

-

\kappa_{i-\frac12,j}

\frac{T_{i,j}^{n}-T_{i-1,j}^{n}}{\Delta x}

\right]

\]

\[

+

\frac{1}{\Delta y}

\left[

\kappa_{i,j+\frac12}

\frac{T_{i,j+1}^{n}-T_{i,j}^{n}}{\Delta y}

-

\kappa_{i,j-\frac12}

\frac{T_{i,j}^{n}-T_{i,j-1}^{n}}{\Delta y}

\right]

\]

The lecture focused on evaluating the coefficient and derivative at the midpoint between nodes. Since the temperature field is solved at integer-indexed nodes, the midpoint conductivity can be approximated by averaging neighbouring values:

\[

\kappa_{i+\frac12,j}

\approx

\frac{\kappa_{i,j}+\kappa_{i+1,j}}{2}

\]

The lecturer noted that this midpoint value can also be viewed as a linear interpolation between the neighbouring nodal values.

The coding demonstration used nested loops:

1. A time loop.

2. A loop over the \(x\)-coordinate.

3. A loop over the \(y\)-coordinate.

Different conditional statements were needed for the different boundaries because each boundary may have a different boundary condition.
