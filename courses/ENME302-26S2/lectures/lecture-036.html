Convexity and optimisation

The lecture then returned to Chapter 12 and optimisation. A simple upward-opening parabola was used as an intuitive example of a convex function. Convexity is useful because minimisation is generally easier to reason about when the objective function has a single basin rather than many local minima.

A noisy or non-convex objective function may contain multiple local minima. A local optimisation method can become trapped in one of them rather than finding the global minimum.

The lecturer reviewed three ways to assess convexity:

1. The epigraph.

2. Jensen’s inequality.

3. The Hessian or second derivative.

Jensen’s inequality

For two points \(x_A\) and \(x_B\) in the solution set and a parameter \(\theta\) between 0 and 1, Jensen’s inequality was presented in the standard convex-function form:

\[

f\left((1-\theta)x_A+\theta x_B\right)

\leq

(1-\theta)f(x_A)+\theta f(x_B),

\qquad 0\leq\theta\leq1.

\]

The point on the left is a point between \(x_A\) and \(x_B\). The right-hand side is a linear interpolation between the function values at the two endpoints.

Geometrically:

• The line segment between \((x_A,f(x_A))\) and \((x_B,f(x_B))\) is constructed.

• The function is evaluated at every intermediate point.

• For a convex function, the function lies below or on the line segment.

• If the function rises above the line segment over any interval, the function is non-convex over that interval.

The lecturer demonstrated this concept with Python code:

• A function such as \(f(x)=x^2\) was evaluated over an interval approximately from \(-3\) to \(3\).

• Several pairs of points were selected, apparently using random sampling.

• Intermediate \(\theta\) values were used to generate points between each pair.

• The code checked whether the Jensen inequality was satisfied.

• The loop could terminate when a non-convex interval was found.

The lecturer emphasised the importance of adding axis labels and legend entries to plots. Without them, it is difficult to determine what the plotted curves represent.

For a non-convex example, the function was shown to lie above the line segment connecting two points. This violates the convexity inequality for that interval.

Hessian test

For a twice-differentiable function, convexity can be checked using second derivatives.

In one dimension:

\[

f''(x)\geq 0

\]

indicates convexity over the interval being considered.

For a multivariable function, the equivalent object is the Hessian matrix:

\[

\nabla^2 f(\mathbf{x}).

\]

The function is convex if the Hessian is positive semi-definite throughout the relevant solution domain.

Examples discussed:

• For \(f(x)=x^2\):

\[

f''(x)=2>0,

\]

so the function is convex.

• For \(f(x)=x^3\):

\[

f''(x)=6x.

\]

The sign changes depending on \(x\), so the function is not globally convex or globally concave over the entire real line. It is convex where \(x>0\) and concave where \(x<0\), subject to the interval under consideration.

• A linear combination of variables can be expressed using vector notation, approximately as:

\[

f(\mathbf{x})=\mathbf{a}^{T}\mathbf{x}+b.

\]

A linear function is convex because its graph coincides with the line segment used in Jensen’s inequality.

Global and brute-force methods

The lecturer introduced direct approaches to finding a minimiser by exploring the parameter space.

A complete brute-force search evaluates every possible combination of variables. This is usually computationally expensive and may be impractical for experiments or high-dimensional problems.

Two sampling-based methods were discussed:

#### Monte Carlo search

Monte Carlo search samples the parameter space randomly. If the samples are distributed reasonably throughout the domain, some should fall near low objective-function values.

Advantages:

• Can explore the entire domain.

• Does not focus only on one starting point.

• Can provide an initial understanding of the global structure.

Limitations:

• Random sampling may miss a narrow minimum.

• Many samples may be needed, especially in high-dimensional spaces.

• It does not necessarily refine the best point efficiently.

#### Grid search

Grid search samples the parameter space systematically on a grid. It is more methodical than Monte Carlo sampling but can also become expensive as the number of parameters increases.

Both Monte Carlo search and grid search were described as global methods because they explore the full solution domain rather than following only one local path. They are therefore less likely to be trapped immediately by a local minimum, although a finite sampling scheme cannot guarantee that the true global minimum is found.

Steepest descent

Steepest descent improves a solution by moving downhill in the direction of the negative gradient.

Starting from an initial point \(\mathbf{x}_0\), the general update is:

\[

\mathbf{x}_{k+1}

=

\mathbf{x}_k-h\nabla f(\mathbf{x}_k),

\]

where:

• \(\nabla f(\mathbf{x}_k)\) is the gradient.

• \(h\) is the step factor or step size.

• The negative sign moves in the direction of decreasing objective function.

The method is iterative:

1. Choose an initial point.

2. Evaluate the gradient.

3. Move in the negative-gradient direction.

4. Repeat.

5. Stop when the gradient magnitude is sufficiently small.

A typical convergence criterion is:

\[

\left\|\nabla f(\mathbf{x}_k)\right\|<\varepsilon,

\]

where \(\varepsilon\) is a specified tolerance.

When the gradient approaches zero, the algorithm may have reached a local minimum. For a convex function, this local minimum may also be the global minimum.

The gradient determines both direction and, in the basic fixed-step formulation, the scale of the proposed movement:

• Large gradients produce larger changes in \(\mathbf{x}\).

• Small gradients produce smaller changes near a stationary point.

Step-size effects

A suitable step size is critical.

For a well-behaved convex function and a reasonable step size, the iterations move toward the minimum.

If \(h\) is too large:

• The algorithm can overshoot the minimum.

• The objective function may increase from one iteration to the next.

• The iterations can bounce across the minimum.

• The sequence can diverge rather than converge.

The lecturer demonstrated this using a parabola. A large step repeatedly moved the iterate to the opposite side of the minimum, where the objective function was higher. Repeating the same update caused the iterates to move farther away.

If \(h\) is small:

• The method is more stable.

• Progress can be very slow.

• Many iterations may be required to approach the minimum.

The lecture included a Python demonstration using a quadratic function. The transcript identifies the function as a scaled \(x^2\) expression, apparently with a factor of one-half so that differentiation gives a simpler gradient. An initial step factor of approximately \(3.1\) was used to illustrate divergence. A smaller step factor produced slow but improving convergence.

Line search

A line search improves steepest descent by selecting a suitable distance to move along a chosen descent direction.

If the descent direction is defined as:

\[

\mathbf{d}=-\nabla f(\mathbf{x}),

\]

then the ideal line-search step solves:

\[

h^\ast

=

\arg\min_{h\geq 0}

f(\mathbf{x}+h\mathbf{d}).

\]

This would find the best point along the current descent line. However, evaluating every possible value of \(h\) is itself expensive. The lecture therefore introduced heuristic line-search methods.

Backtracking line search

Backtracking line search:

1. Starts with a relatively large step factor \(h\).

2. Evaluates the candidate point \(\mathbf{x}+h\mathbf{d}\).

3. Checks whether the objective function has improved sufficiently.

4. Reduces \(h\), for example by multiplying it by one-half, if the condition is not met.

5. Repeats until an acceptable step is found.

The lecture referred to a condition of the general form:

\[

f(\mathbf{x}+h\mathbf{d})

\leq

f(\mathbf{x})+\beta h\nabla f(\mathbf{x})^{T}\mathbf{d},

\]

where \(\beta\) is a small positive parameter. The exact notation was partially unclear in the automated transcript, but the role of the parameter was described as follows:

• A small \(\beta\) makes the sufficient-decrease requirement less demanding.

• A larger \(\beta\) requires a more substantial decrease.

• A typical value mentioned was approximately \(10^{-4}\).

The line search allowed the algorithm to begin with a large trial step while preventing divergence by reducing the step whenever the candidate point was not sufficiently better.

Penalty functions and soft constraints

The lecture then considered optimisation subject to constraints. Examples of constraints included:

• Meeting a performance requirement.

• Staying within a budget.

• Restricting a design variable to a permissible range.

Instead of using a dedicated constrained-optimisation method, the lecture introduced a soft constraint by modifying the objective function:

\[

\tilde{f}(\mathbf{x})

=

f(\mathbf{x})+\alpha P(\mathbf{x}),

\]

where:

• \(f(\mathbf{x})\) is the original objective function.

• \(P(\mathbf{x})\) is a penalty function.

• \(\alpha\) controls the importance of constraint violations.

For an example constraint of the form:

\[

x_1\leq 5,

\]

a penalty function was described as:

\[

P(x_1)=\max(0,x_1-5).

\]

This penalty behaves as follows:

• If \(x_1\leq5\), then \(P(x_1)=0\).

• If \(x_1>5\), then the penalty increases linearly with \(x_1-5\).

The combined objective is unchanged in the allowed region and becomes larger when the constraint is violated.

Increasing \(\alpha\):

• Makes violations more costly.

• Produces a steeper penalty region.

• Encourages the optimiser to remain closer to the feasible region.

However, the penalty method is only a soft constraint. Depending on the penalty coefficient and stopping tolerance, the optimiser may settle slightly outside the permitted region. The lecturer described this approach as a practical modification of an unconstrained problem rather than a strictly enforced constrained-optimisation method.

A quadratic penalty can also be used, for example in a form proportional to:

\[

P(x_1)=\max(0,x_1-5)^2.

\]

A quadratic penalty grows faster than a linear penalty as the violation increases. This can enforce the constraint more aggressively, but it also changes the objective landscape and introduces bias into the location of the computed optimum.

Simulation-driven design

The lecture connected optimisation to simulation-driven design.

A conventional engineering design workflow was described as involving stages such as:

1. Planning.

2. Concept design.

3. Preliminary design.

4. Detailed design.

5. Verification.

6. Production.

In the conventional workflow, numerical methods such as computational fluid dynamics and finite-element analysis are often used during detailed design. These simulations can be computationally expensive, so they are traditionally applied after the preliminary design has already been selected.

Simulation-driven design uses simulation and optimisation earlier, during the exploration stage. This can reveal useful design directions before the design becomes expensive to revise.

The lecturer used a beam example:

• The left-hand side of the beam is fixed to a wall.

• A load is applied.

• The objective is to minimise the beam mass while retaining the required structural performance.

Three optimisation levels were distinguished:

#### Parameter optimisation

Parameter optimisation varies a limited number of selected design variables, such as reference points or dimensions. The overall form of the beam remains constrained by the chosen parameterisation.

#### Shape optimisation

Shape optimisation changes a boundary, such as the lower boundary of the beam. This provides more design freedom than changing only a few parameters but still retains the same general topology.

#### Topology optimisation

Topology optimisation permits more fundamental changes to the material layout:

• The design no longer needs to remain rectangular.

• Internal holes can form.

• The final geometry may be non-intuitive.

• The solution may use less material while meeting the simulated loading requirements.

The lecturer noted that topology-optimised designs may require engineering refinement before manufacture. For example:

• Small holes may be difficult to manufacture.

• Very thin regions may not be sufficiently robust.

• Simulation assumptions and constraints must be checked.

• The result provides a starting point for a manufacturable design rather than necessarily being the final component.

Local versus global optimisation

A student asked about becoming trapped in a local minimum. The lecturer confirmed that multimodal problems can cause steepest descent to converge to a local rather than global minimum.

Because the full objective function is generally unknown, the optimiser cannot tell automatically whether the current minimum is the best one in the entire domain.

A practical combined strategy is:

1. Use Monte Carlo sampling or grid search to survey the parameter space.

2. Identify promising low-objective regions.

3. Apply steepest descent or another local method to refine the solution.

This combines the global exploration capability of sampling methods with the efficient local refinement of gradient-based optimisation.

The right-hand side is the value of the straight-line interpolation between the endpoint function values.

One-dimensional second-derivative test

For a twice-differentiable function,

\[

f''(x)\geq0

\]

is the standard local condition for convexity.

Example:

\[

f(x)=x^2,

\qquad

\]

Hessian condition

For a multivariable twice-differentiable function, convexity is associated with a positive semi-definite Hessian:

\[

\nabla^2 f(\mathbf{x})\succeq0.

\]

This means that for every vector \(\mathbf{v}\),

\[

\mathbf{v}^{T}\nabla^2 f(\mathbf{x})\mathbf{v}\geq0.

\]

The exact matrix test was not expanded in the lecture transcript.

Linear objective

A linear function can be written approximately as:

\[

f(\mathbf{x})=\mathbf{a}^{T}\mathbf{x}+b.

\]

Linear functions are both convex and concave because their graph coincides with its secant line.
